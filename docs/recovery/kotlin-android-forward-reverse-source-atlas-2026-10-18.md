# Forward–reverse source atlas for Kotlin / Android recovery
**Survey checkpoint: 2026-10-18.** Authority: AAR-private DLE #82. Experiments live in public AAR draft PR #39; stateless tool images in separate PR #41. Source *availability* is not evidence of original app source recoverability, permission to transfer SDK binaries, or permission to analyze an unauthorized app.

## Highest-value finding from *source*, not just tooling menus

R8's `KotlinMetadataRewriter.runForR8` operates on actual `@kotlin.Metadata` and can remove/rewrite metadata when the class/annotation is pruned or its keep conditions are not met. JADX's Kotlin Metadata plugin consumes such metadata, renames getters/fields and adjusts data class annotations. Therefore a Kotlin metadata feature switch that leaves compiler diagnostics unchanged may reflect **absent/pruned metadata**, a different source of failure (e.g., Java overload resolution), or a pass that had no matching patterns. Without an independent metadata-presence probe, **none** is established.

The exact same source-known study `#39104459317` (JADX 1.5.6 built-in options) tested four modes against *both* R8-shrunk golden variants. All eight had identical target Java hashes and compiler diagnostic categories by mode, JAVAC still failed. Retain this negative result; do not repeat the same flags on the same fixture without changing a causal hypothesis. The relevant JVM overload-resolution source is `jadx-core/src/main/java/jadx/core/dex/visitors/MethodInvokeVisitor.java`.

## Minimal prioritized DoE, no broad ecosystem reimplementation

1. **Metadata survival/origin (next, P0):** On Kotlin 2.0.21 source-known raw classfiles, D8 DEX and five R8 variants, inventory `@Metadata` presence, versions, generated member signatures and annotation bytes; one independent parser based on version-qualified Kotlin Metadata or ProGuardCORE, plus the existing JADX view. Ground flags in R8 KotlinMetadataRewriter / official AGP R8Task sources. Produce `PRESENT/REWRITTEN/REMOVED/UNKNOWN` receipts. Source ground truth stays evaluator-only in blind actor interviews.
2. **Target structural cause (P0):** On shrink-only (one unidentified JAVAC category) and shrink+optimize (missing symbol 2, visibility 4, overload 2), compare method signatures/access and preserved call refs from dexlib2/Androguard to JADX `MethodInvokeVisitor` output and actual Kotlin lowering. Classify R8 removal vs JADX invalid Java generation; use only the already source-known golden. Keep existing strict postrepair unchanged; do not auto-enlarge pattern counts.
3. **One local source instrument (P1):** Compile/test a *separate* source-pinned JADX visitor trace or plugin with only read-only diagnostic output: method hash, pass ID, invocation/field flags, selected cast decision, counts. Compare raw tool result against pinned 1.5.6 jar in disposable OCI. Escalate to a source patch **only if** a falsifiable issue appears in the traced pass. No arbitrary script/plugin install in production cell.
4. **Disjoint holdouts (P1):** Kotlin compiler synthetic (data, default parameter, inline, suspend), Kotlinx Serialization, Coroutines, Compose, with library source and versions locked. Add ReDex-generated distinct optimizer holdouts if the first probe earns it. A forward fixture must have a source-known JVM and (later admitted) ART behavior oracle before attributing behavioral differences to recovery.
5. **Packaging/runtime/native (P2):** Bundletool AAB/split topology, AndroidX UI/framework, JNI Ghidra/ART. Keep CDR device authorization, R8/Android SDK licensing, and private-app corpus admission separate.

For each specimen: `app/APK SHA -> dependency+compiler+R8 source/binary commits -> class or DEX hash -> transform/metadata ledger -> raw independent parser and JADX view -> repair hypothesis -> compiled behavioral oracle -> holdout status`. Return `UNKNOWN` when any link is missing.

**Negative space:** Kotlin/R8/Jetpack source does **not** contain private application source; R8 legitimately removes information; Play Services backend and many vendor/protector implementations are not equivalent to full open AOSP. No amount of source study can reconstruct erased logic or remote-only behavior without other evidence. No default full SDK image publication. Distinguish tool/source license (e.g., Kotlin/AndroidX/JADX Apache-2.0, R8 BSD-style, ReDex MIT, ProGuard main GPL) from rights in third-party APKs and Android SDK redistribution terms.

**Process:** Use Discover -> Observe -> Plan -> Apply -> Verify. The immediate proof is a *single metadata survival experiment on the existing golden*; no additional generic census framework, arbitrary cloud API access, MCP servers, or expensive native Ghidra stage. Preserve existing PR #39 and PR #41 authority.
